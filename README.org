#+title: wime
#+options: toc:nil num:nil

wime 是纯 Elisp 的中文输入法，用来取代 emacs-rime。
输入方式是双拼（默认微软双拼）加大写的墨奇辅助码，词库取自万象拼音。
打字时先由词典词格给出候选；
停键后，本地神经模型在后台重新解码，并从你的纠正中学习。
同一个后台也提供日文输入法 =wime-japanese= （AZIK 输入，见[[*日本語][日本語]]）。

* 使用

** 按键

| 按键                          | 作用                               |
|-------------------------------+------------------------------------|
| 小写字母，及方案用到的 =;,./= | 双拼编码，两键一个音节             |
| 大写字母                      | 前一个音节的辅助码，如 =niK=       |
| 数字                          | 选候选；分段视图里选该段的替代写法 |
| 空格                          | 确认文字，结束自动选字             |
| =RET=                         | 当前输入按原始英文按键上屏；没有活动输入时执行原来的回车命令 |
| =DEL=                         | 删掉最后一个键                     |
| =ESC=                         | 半上屏模式暂存；旧模式取消           |
| =TAB=                         | 在分段视图和整句列表之间切换       |

=;,./= 只在方案用到的位置（声母位或韵母位）算编码，别处仍是标点。
标点默认上屏全角，=M-x wime-toggle-punctuation= 切换为半角。
只读缓冲区里按键原样透传。

wdoom 默认启用 =wime-editable-preedit=：候选是 buffer 中的真实文字，
读音作为不写入文件的属性保存。可直接移动光标，在待转换字后补大写辅助码；
=C-\\= 切换英文不会丢掉中文的读音，再切回即可继续改字。
普通插入和粘贴作为原样文字，把相邻中文段分开；明确选定的字保持固定。
未确认中文按最多 =wime-edit-max-syllables=（默认 24）字的窗口重新转换，
后输入的音节可改变前面的选字。英文和标点两侧目前分别转换，尚不做跨段联合解码。
=ESC= 暂存并进入 Evil normal，用背景色和下划线标记；
回到 insert 后可继续修改。未启用 Evil 时只暂存。
中文输入状态下，空格确认可访问区域内的待转换文字（包括已暂存的），
再按空格正常输入空格。=C-c C-c= 保留原编辑模式的功能。
设 =wime-editable-preedit= 为 nil，或在 buffer 中关闭 =wime-edit-mode= 可用旧界面。

** 分段视图

=wime-candidate-style= 为 =spans= 时（wdoom 装了重排模型后的默认），
半上屏隐藏双拼串，大写辅助码以小号上标贴在对应汉字旁，暂存后仍保留。
模型拿不准的字加波浪线，替代写法在对应字词下方竖排，整段统一编号。
双拼和辅助码仍保存在读音记录中，可继续补码纠错。
按数字把那一段固定下来，其余部分重新解码；
固定的字在它的按键改变前一直有效。

** 启用

wdoom 的 =wdoom-input= 模块会配置好一切。单独使用时：

#+begin_src emacs-lisp
(require 'wime)
(setq wime-database-file "/path/to/wanxiang.db")
(wime-setup)                            ; default-input-method 设为 "wime"
#+end_src

可选的 octagram 搭配评分需要 =wime-grammar-module= 和 =wime-grammar-shared-dir=。
神经模型见下文。

* 工作方式

** 词格

词库是按双拼码索引的 SQLite。
多音节输入在词格上做 beam 搜索，每个音节边界保留 =wime-search-width= 条读法，
打分是词频对数、每词罚项 =wime-word-penalty= 和可选的 octagram 分数。
追加、退格、改辅助码时复用仍然有效的前缀。
辅助码在词格里是硬约束。

** 神经阶段

停键 40 ms 后，wime 把输入发给常驻的 CUDA worker（=neural/gpu-worker.py=），
结果回来时如果输入没变，就替换显示的候选。
worker 出错或超时，词格候选照常可用。
=wime-neural-search-method= 选择做法：

- =decode= :: 不经过词格。Qwen HF 与 MiniCPM 原生共用 =neural/text_decoder.py=：
  token 的原始字节必须满足读音、辅助码和固定字约束；25M 模型只引导有限宽度搜索，
  最终按完整文本的通用模型概率和用户学习偏好排序。
  支持半音节、跨上屏边界的 token 修复，以及重复请求缓存。
- =verify= :: 词格给出候选池，25M 模型（可加通用模型重排）从中挑选，
  并提出更可能的前缀交给词格重搜。缺少大模型时 wdoom 用它。
- =rerank= :: 旧的 Rust CPU worker 的无条件重排，需要相应的模型。

条件模型只支持微软双拼；其他方案只用词格。

** 纠错学习

设置 =wime-user-database= 后（wdoom 为 =$XDG_DATA_HOME/wime/user.sqlite3=），
每次上屏完整读音都记录按键、上屏文本、wime 首先给出的读音和光标前文。
这份日志只存本机，也是真实使用的评测数据。

上屏的文本与首选不同时，不同的片段会被扩展成同键下最短的词典词
（至少两字），记为学到的读音；同样的按键再上屏别的读音，就忘掉它。
学到的读音在词格和神经阶段都有强偏好，模型不会推翻你的纠正。

=M-x wime-memory= 管理学习偏好，=M-x wime-history= 查看上屏历史；
wime-lab 中也可按 =l/H= 打开。=/= 搜索，=RET= 查看详情，=e= 修改词语和编码，
=m/u= 标记或取消标记，=d= 删除标记记录（无标记时删除当前行），=U= 撤销。
撤销记录保留到管理 buffer 被关闭；=+= 加载更多，=g= 刷新。
启用 Evil 时进入普通状态，保留移动与搜索键；=s= 筛选，=H/L= 切换历史与学习偏好，
=m/M= 标记或取消标记，=u= 撤销，=gr= 刷新，=g?= 查看当前按键；详情、修改、删除仍用 =RET/e/d=。
删除上屏历史保留学习偏好，删除偏好也保留历史。修改读音会按当前词库校验。
=M-x wime-memory-at-point= 查找选区、当前候选或光标处文字中的学习词语。

* 安装神经模型

模型、Python 和本机编译的 CUDA 库放在 =$XDG_DATA_HOME/wime/=
（默认 =~/.local/share/wime/=），不进 wdoom 快照。

| 中文后端 | 模型目录 | 运行方式 |
|----------+----------+----------|
| =verify= | 条件模型 | 词格候选校验；不加载通用大模型 |
| =qwen-hf=（默认） | =rescorers/Qwen3.5-2B-Base/= | Transformers BF16 |
| =minicpm-native= | =rescorers/MiniCPM5-2B/= | llama.cpp BF16 GGUF；HF 只负责分词 |
| =legacy= | =rescorers/Qwen3.5-2B-Base/= | 原字符同步搜索；25M 条件模型与 Qwen HF 融合排序 |

25M 条件模型仍为 =models/<sha256>.safetensors=；打包哈希固定在
=neural_model.bzl=，也可用 =WIME_CONDITIONAL_MODEL= 指向同一文件。
=qwen-hf= 与 =minicpm-native= 使用相同的字节约束搜索配置；=legacy= 保留
原搜索和融合排序，便于运行时回切对照。

#+begin_src sh
uv venv --python 3.12 ~/.local/share/wime/python
uv pip install --python ~/.local/share/wime/python/bin/python \
    -r emacs-packages/wime/neural/requirements-gpu.txt
#+end_src

Qwen 的完整 HF 模型下载到上表目录即可。MiniCPM 先准备本地 HF 模型下载，
再从当前 workspace 构建已经导入的 llama.cpp，安装匹配的 tokenizer 和 BF16 GGUF：

#+begin_src sh
~/.local/share/wime/python/bin/python emacs-packages/wime/neural/prepare-native.py \
    --model-dir /path/to/MiniCPM5-2B \
    --gguf /path/to/MiniCPM5-2B-BF16.gguf --cuda-architectures 89
#+end_src

=89= 对应 RTX 4090，其他 GPU 使用其 CUDA 架构编号。构建需要 CMake、Ninja 和
CUDA toolkit；=--nvcc= 可指定编译器。没有现成 GGUF 时省略 =--gguf=，并用
=--convert-python= 指定装有 llama.cpp 转换依赖的独立 Python 环境；转换固定为 BF16。
安装器校验模型结构和精度，拒绝覆盖不同的已安装模型，按源码及编译器标识保存独立库版本。
运行时从 =native/current/lib/libwime_llama.so= 选择版本，检查点保存解析后的具体路径。

=./wdoom/bin/wdoom-prepare --native= 打包 worker、Elisp 和 25M 模型，重启后生效。
=M-x wime-select-backend= 选择 =verify=、=qwen-hf=、=minicpm-native= 或 =legacy=：先预热，再等当前
输入结束后切换，并保存下次启动配置；失败保留当前 worker。
=verify= 只用词格和条件小模型，不加载通用大模型，也不支持日文转换。
缺少大模型时保留 25M 的 =verify=；worker 出错时词格候选仍可用。
=M-x wime-lab= 的评测、试输、检查点保存也携带后端和原生模型路径。
MiniCPM 原生目前只支持中文；日文输入使用 Qwen HF，切换界面会检查这一限制。

* 日本語

=M-x set-input-method= 可选择四个方案：

| 名称 | 键位与规则 | 运行时规则表 |
|------+------------+--------------|
| =wime-japanese-base= | QWERTY + 普通罗马字：=shi= し、=chi= ち、=tsu= つ | =japanese/base.eld= |
| =wime-japanese= | QWERTY + AZIK：=kz= かん、=kp= こう、=ds= です | =japanese/azik.eld= |
| =wime-japanese-onishi= | [[https://o24.works/layout/][原版大西配列]] + 普通罗马字 | =japanese/romaji.eld= |
| =wime-japanese-onishi-azik= | [[https://zenn.dev/maki10645/articles/68f7c10a018691][文章版大西 AZIK]]，包括 J/Z 交换 | =japanese/onishi-azik.eld= |

大西键位只在日文输入时由 wime 重排，系统和键盘固件保持 QWERTY。
四套方案的促音都用逻辑键 =;=，在大西配列中是 QWERTY 的 =B= 位置。
文章版用 =c= 输入 ん；子音后 =n/s/r/h/t= 对应 an/in/un/en/on，
=c/,/v/l= 对应 ou/ai/ei/uu，小假名用 =l= 前缀。
它不沿用普通 AZIK 的 =ds= です、=ms= ます等词级简写。
四个方案统一编辑 =japanese/rules.eld= 后生成，分别位于 =:base=、=:azik=、=:onishi=、=:onishi-azik=：

- =:inherits= 继承另一个方案。=:onishi= 默认继承 =:base= 的普通罗马字规则，只覆盖键位。
  子方案可以覆盖字段；列表整体替换，显式空列表会清空父方案的同名字段。
- =:layout-rows= 是物理键位重排，四个方案各自配置；base 和原版 AZIK 默认保持 QWERTY。
- =:rows= 绑定假名行，如 =("hg" "hy")= 表示用 hg 输入 hy 行。
  行内可用 =:vowels= 和 =:extensions= 限定参与生成的元音、后缀，空列表表示禁用。
- =:extensions= 定义后缀，如 =(ei "v" "e" "い")= 表示子音 + v 输出 e 段假名 + い；
  将 v 改成 q，就会把 =kv= けい、=gyv= ぎぇい等整组改到 q。
- =:extension-extras=、=:extension-overrides= 按后缀 ID 定义例外，修改后缀键时也会一起移动。
- =:nasal-keys= 配置独立的 ん，=:sokuon-key= 配置促音。
  单条增补、删除、覆盖分别用 =:extra-rules=、=:remove=、=:overrides=；重复绑定会报错。
  原版 AZIK 的词级简写也在这里维护；=:literal-rules= 保留历史标点和 Shift 别名。

在仓库根目录执行：

#+begin_src sh
emacs -Q --batch -l emacs-packages/wime/gen/japanese.el -f wime-japanese-generate
#+end_src

生成 =base.eld=、=azik.eld=、=romaji.eld=、=onishi-azik.eld= 和 =layouts.eld=，不访问 ddskk 或网络。
将命令最后一项换成 =wime-japanese-check= 可以只检查产物是否过期。
重新启用输入法会重读规则和键位；wdoom 的快照需重新打包后使用。
规则表每行一条 =(按键 假名 [剩余按键])=，行尾注释是等效普通罗马字。
表里的按键是重排后的逻辑键；换方案用 =M-x set-input-method=，各缓冲区独立。
预编辑区显示已转换的假名和还在等待的键；
数字选候选，空格上屏当前候选， =RET= 上屏假名， =DEL= 删键， =ESC= 取消。

按住 Shift 敲的假名要写成汉字或片假名（加下划线显示），
如 =KAku= 書く、 =TAKq= 高い、 =GA:KOU= 学校（Shift 下的 =;= 是 =:= ，仍打 っ）。
一段输入里只要用过 Shift，没按 Shift 的假名就保持平假名；
完全不用 Shift 时由模型决定写法。
AZIK 双键出两个假名时，第一个假名跟第一个键，其余跟最后一个键（ =Yq= ＝ 焼い）。

停键后 worker 解码假名：Qwen 的 token 在读音表约束下拼出假名，
每个假名位置与 23M 假名条件模型融合（ =neural/japanese.py= ）。
还在等待的键只允许它们能开头的假名作为暂定的最后一个字。
没有待定键时，azooKey 的 zenz 模型自己生成的候选也加入，
但只留读音表能从所敲假名拼出的（自由生成可能漏字），
全部按 zenz 与 Qwen 的整句概率重排。
平假名和片假名始终在候选里。尚无纠错学习。

wdoom 在 =$XDG_DATA_HOME/wime/japanese/= 下找到两个文件时启用：

- =kana-model.safetensors= :: =neural/train-japanese.py= 训练的假名模型。
- =readings.json= :: Qwen 词表的读音表：

#+begin_src sh
python neural/build-japanese-lexicon.py --out lexicon.json   # fugashi + UniDic 的环境
python neural/build-japanese-table.py \
    --rescorer ~/.local/share/wime/rescorers/Qwen3.5-2B-Base \
    --lexicon lexicon.json \
    --out ~/.local/share/wime/japanese/readings.json
#+end_src

读音来自 JMdict 和 KANJIDIC2（Tagaini Jisho 软件包里的数据库），
加上训练语料里出现过的 UniDic 词和 JMnedict 专有名词，
每个读音只留语料里最常见的 4 个新写法。
训练语料及其许可固定在 =neural/japanese-sources.json= ；
=prepare-japanese.py= 用 MeCab + UniDic 3.1 注音，
排除 2025–26 年加入 Tatoeba 的测试句，
=evaluate-japanese.py= 和 =test/record-japanese.el= 在这些句子上评测。

可选的 =zenz/= 目录启用重排，由 zenz-v3.2-small（Apache-2.0）的 gguf 转换：

#+begin_src sh
PYTHONPATH=llama.cpp/gguf-py python neural/convert-zenz.py \
    ggml-model-Q5_K_M.gguf ~/.local/share/wime/japanese/zenz
#+end_src

* 词库

Bazel 在构建时下载上游 nightly 产物，不依赖本机安装：

- =rime_wanxiang.bzl= 按固定 URL 和 sha256 拉取万象的墨奇辅助码词库
  和 octagram 模型 =wanxiang-lts-zh-hans.gram=。
  =gen/update_nightly.py= 更新到最新的 nightly 并改写 sha256。
- =gen/wime_gen.py= 移植万象的拼写运算，把词库转成按双拼码索引的 SQLite。
- =//emacs-packages/wime:database= 生成 =wanxiang.db= （微软双拼）。
  =schemes/= 下的表生成其他方案：
  =database_liangti= 是按实测击键成本优化的量体双拼，
  =database_liangti_fast= 是只求最快的量体双拼·速。
  用 =M-x wime-select-database= 切换。

每个库的 =meta= 表记录方案名和声母位、韵母位用到的键。

* 开发

ERT 测试在仓库根目录通过已准备的 wdoom 快照运行。隔离状态目录并禁用个人词库，
避免测试写入真实输入记录：

#+begin_src sh
WDOOM_STATE_DIR=$(mktemp -d) ./wdoom/bin/wdoom --batch \
  --eval '(setq wime-user-database nil
                native-comp-enable-subr-trampolines (make-temp-file "wdoom-trampolines" t))' \
  -l ert -l emacs-packages/wime/test/wime-test.el \
  -l emacs-packages/wime/test/wime-edit-test.el \
  -l emacs-packages/wime/test/wime-edit-neural-test.el \
  -l emacs-packages/wime/test/wime-neural-test.el \
  -l emacs-packages/wime/test/wime-japanese-test.el -f ert-run-tests-batch-and-exit < /dev/null
#+end_src

Python 测试不需要 GPU 和模型，但需要 =neural/requirements-training.txt= 里的依赖：

#+begin_src sh
cd emacs-packages/wime/test && python -m unittest
#+end_src

模型训练与评测在 =neural/=：

- =prepare-*.py= :: 准备语料：对话（LCCC）、技术文档、成语专名，
  以及本地和 =domain-sources.json= 中固定版本的外部技术文档。
  都按原始对话或文档划分训练、验证和测试集。
- =train-conditional.py= :: 训练 25M 条件模型。
- =evaluate-conditional.py= :: 用真实词库和 octagram 评测，
  =--search-method decode= 评测 =decode=。

=test/record-conditional.el= 经过真实的异步路径评测，
设置 =WIME_TYPING_INTERVAL= 时逐键输入。

=test/*-measurements.json= 等文件记录了各项选型背后的测量。
模型实现及其上游历史在 =third_party/chinese-ime-lm/=。
