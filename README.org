#+title: wime
#+options: toc:nil num:nil

wime 是取代 emacs-rime 的纯 Elisp 输入法，针对万象 pro 的双拼加大写墨奇辅助码。双拼方案随数据库走：默认微软双拼，也可以用 =schemes/= 里按表生成的方案。输入解析和词格搜索在 Elisp 内完成；可选的原生模块提供 octagram 评分，后台进程提供本地神经重排。

* 输入模型

- 输入按音节解析：两个编码键构成一个音节（字母，加上方案用到的 =;,./=；它们只在方案使用的位置——声母位或韵母位——算编码，别处仍是标点），紧随其后的大写字母是该音节的墨奇辅助码；辅助码之后再出现小写就开启下一音节。因此 =yrZt= 保持原样显示，不会把 =Z= 挪到 =t= 后面。
- 单音节直接查字表；多音节搜索词格，在每个音节边界保留最多 =wime-search-width= 条不同表记（默认 8）。整句在前，较短前缀在后；每个候选保留消耗的音节数和整词命中信息。追加、退格和辅助码修改复用仍有效的前缀路径，句尾的 octagram 分数重新计算。
- 打分用词频对数、每词罚项（=wime-word-penalty=）和可选的 octagram 搭配分数。
- 数字选字、空格选当前、回车提交原始输入、退格依次回退已输入的键、ESC 取消；只读缓冲区原样透传。

* 数据与生成

Bazel 在构建期从上游 nightly 产物下载，不依赖本机安装，也不导入整个仓库：

- =rime_wanxiang.bzl= 按固定 URL 与 sha256 拉取 =dict-nightly= 的 =rime-wanxiang-moqi-fuzhu.zip=（墨奇辅助码只存在于 release，git 树里的 =chaifen.txt= 是空占位）。
- 同一个文件里的 gram 规则拉取 =RIME-LMDG= 的 =wanxiang-lts-zh-hans.gram=，随快照发布，供 octagram 模块使用。
- =gen/update_nightly.py= 重新下载两个 nightly 资产并回写 =rime_wanxiang.bzl= 里的 sha256，用于跟随 nightly。
- 生成器 =gen/wime_gen.py= 解析 =wanxiang_algebra.yaml= 的 =pro/微软双拼= 规则（忠实移植 Rime 的 =xform=／=derive=／=xlit=，不依赖 PyYAML），把 =wanxiang_pro.dict.yaml= 及其 =dicts/*.pro.dict.yaml= 转成按双拼码索引的库。
- =--scheme schemes/X.json= 改用表：每个声母（=""= 为零声母）和韵母对应一个键，ü 写作 =v=，j/q/x/y 后的 u 也写作 =v=。表由 =keyboard-ergonomics/export_scheme.py= 从优化结果导出；=schemes/liangti.json= 是量体双拼——按实测击键成本优化、偏好左声右韵的布局，构建目标 =//emacs-packages/wime:database_liangti=（=wanxiang-liangti.db=）；=schemes/liangti-fast.json= 是同一批测量下不顾好记、只求最快的量体双拼·速（=database_liangti_fast=）。用 =M-x wime-select-database= 切换。
- 每个库都带 =meta= 表（方案名、声母位与韵母位用到的键），引擎据此判断 =;,./= 是编码还是标点。
- 产物 =wanxiang.db= 是 SQLite（约 220 万条），由 =//emacs-packages/wime:database= 生成并随快照发布；wime 用内置的 =sqlite-select= 查询。仓库不再提交生成的 Elisp 表。

* 可选神经搜索

wdoom 快照包含 =wime-neural= 和固定摘要的 4.25M 模型，并配置好路径；用 =M-x wime-neural-mode= 启用。独立使用时设置 =wime-neural-program=、=wime-neural-model-file=，worker 可用 =bazel build -c opt //emacs-packages/wime/neural:wime-neural= 构建。模型来源与摘要在 =neural_model.bzl=，推理源码及完整上游历史在 =third_party/chinese-ime-lm/=。

传统候选立即显示，停键 40 ms 后请求模型。默认的 =rerank= 方法最多比较 9 个完整候选，整词命中的首选保持不动。进程常驻并复用模型缓存，最多保留一个正在运行和一个待处理请求。输入、光标、缓冲区内容或选中项变化后，旧结果失效；进程失败或超时保留传统候选。

设置 =wime-neural-search-method= 为 =verify=，并选择 =wime-ms-pinyin-v1= 条件模型，可使用 Zenzai 式的草稿验证与前缀约束重搜。模型读取上文和完整双拼音节序列，一次验证草稿各位置，提出更可能的前缀；Elisp 在词格剪枝前应用约束，因此能找回原候选表之外的读法。默认最多验证 4 次，按模型平均对数概率加上 =wime-neural-prior-weight= 倍的每音节传统评分，选择已验证的完整候选；权重由开发集校准，设为零则只用模型评分。双拼按键和辅助码始终是硬约束；目前条件模型只支持微软双拼，其他方案不启动验证。

默认 worker 使用本地 Rust CPU 推理。可将 =wime-neural-program= 设为本仓库 =neural/gpu-worker.py= 的绝对路径，使用同一条件模型进行本地 CUDA FP32 推理；该脚本需要完整源码目录，以及 PATH 中 Python 提供 =neural/requirements-gpu.txt= 的依赖和可用 CUDA。GPU 模式只支持 =verify=，不使用半精度或 TF32，模型随进程常驻显存。切换 worker 或模型后重新启用 =wime-neural-mode=。首次请求允许 =wime-neural-startup-timeout=（默认 10 秒）完成加载和 CUDA 初始化，后续请求使用普通 2 秒超时；等待或失败时传统候选仍可用。CPU/GPU 对照见 =test/gpu-measurements.json=。

CUDA 可设置 =wime-neural-seed-candidates= 为 =t=，批量评分满足拼音和辅助码约束的完整候选，再从联合评分最高者开始前缀修正。这能处理单字修正漏掉的整词候选；初始批次计一轮验证，预算不等于评分候选总数。当前实验选中继续训练的 25M 模型、=wime-search-width= 16 和验证预算 4。45M 扩容与宽度 32 没有显示更好的开发集结果，完整准确率、真实路径延迟和限制见 =test/scaling-measurements.json=。这些选项仍需主动启用；Rust worker 保留传统草稿。

神经功能仍默认关闭。旧的无条件重排结果见 =test/neural-measurements.json=；条件模型的数据、对照实验和限制见 =test/conditional-measurements.json=。=neural/prepare-conditional.py= 按原始对话划分 LCCC，=neural/prepare-technical.py= 按文档划分固定版本的 Kubernetes 和 Python 中文文档，跨集合重复目标被排除。=neural/train-conditional.py= 只对目标文字计算损失，可用 =--span-share= 将部分训练句子改成接在已提交前缀后的 2～5 字片段，或用 =--layers= 插入初始输出为零的残差层来扩容；=neural/evaluate-conditional.py= 使用真正的词典和 octagram 搜索，=test/record-conditional.el= 验证实际异步 CPU/GPU 路径。评测应使用固定产物副本，避免构建替换正在读取的词典；=--reference-baseline= 可检查每条 octagram 输出是否一致。=test/conditional-debug-cases.json= 保留 100 条纯双拼及 16 条单辅助键对照，属于开发诊断而非独立测试集。金标准不参与模型决策，仅在输出后统计及独立检查词格覆盖率。自动注音和未知的上游预训练重合意味着这些数据不能等同于人工标注的真实按键评测。

尚未实现：上屏后的后续预测、声调输入、自造词与调频。
