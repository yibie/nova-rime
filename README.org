#+title: wime
#+options: toc:nil num:nil

wime 是纯 Elisp 的中文双拼输入法。

- 支持微软、小鹤、搜狗、自然码双拼，大写字母输入墨奇辅助码，
  =C-1= … =C-5= 输入声调。
- 候选来自万象拼音词库的词格搜索；
  有 GPU 时，停键后由本地神经模型重新整句解码。
- 待上屏的文字直接写在 buffer 里，可以移动光标修改、补辅助码，
  拿不准的字就地给出替代写法。
- 同一个后台还提供日文输入法，见 [[file:japanese/README.org][japanese/README.org]]。

* 安装

需要 Emacs 29.1 或更新版本，并带 SQLite 支持：
=(sqlite-available-p)= 应返回非 nil。

#+begin_src sh
git clone https://github.com/0WD0/wime
#+end_src

用 [[https://docs.astral.sh/uv/][uv]] 下载自己方案的词库：

#+begin_src sh
D="${XDG_DATA_HOME:-$HOME/.local/share}/wime"
uvx --from huggingface-hub hf download 0WD0/wime-wanxiang wanxiang.db \
    --repo-type dataset --local-dir "$D"
#+end_src

| 方案     | 文件                  |
|----------+-----------------------|
| 微软双拼 | =wanxiang.db=         |
| 小鹤双拼 | =wanxiang-flypy.db=   |
| 搜狗双拼 | =wanxiang-sogou.db=   |
| 自然码   | =wanxiang-ziranma.db= |

在 init 文件中加入：

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/wime")
(require 'wime)
(setq wime-editable-preedit t
      wime-candidate-style 'spans)
;; 不是微软双拼时：
;; (setq wime-database-file (expand-file-name "wanxiang-flypy.db" wime-data-directory))
(global-set-key (kbd "C-\\") #'wime-toggle-english)
(wime-setup)
#+end_src

=C-\\= 启用中文输入；中文输入时再按切到英文，原样输入字母，
=C-u C-\\= 关闭输入法。
=wime-data-directory= 默认是 =~/.local/share/wime/=
（设置了 =XDG_DATA_HOME= 时在它下面）。

* 使用

| 按键          | 作用                                       |
|---------------+--------------------------------------------|
| 小写字母      | 双拼编码，两键一个音节                     |
| 大写字母      | 前一个音节的辅助码，如 =niK=               |
| =C-1= … =C-5= | 前一个音节的声调；=C-5= 是轻声，不筛选候选 |
| 数字          | 选候选；分段视图里选那一段的替代写法       |
| 空格          | 确认文字                                   |
| =RET=         | 按原始按键上屏英文                         |
| =DEL=         | 删掉最后一个键                             |
| =ESC=         | 暂存待上屏的文字                           |
| =TAB=         | 在分段视图和整句列表之间切换               |
| =C-\\=        | 切换中文与英文                             |

声调只保留带这个调的字；词里的变调不影响筛选，打字典里的本调即可。
方案用到 =;,./= 时，它们只在编码位置算键，别处仍是标点。
标点默认全角，=M-x wime-toggle-punctuation= 切换半角。

** 半上屏

=wime-editable-preedit= 打开时，待上屏的中文就是 buffer 里的文字，
读音作为属性保存，不写进文件。

- 光标可以移回去，在字后补大写辅助码，或删改其中的字。
- 继续输入时，最近 =wime-edit-max-syllables= （默认 24）个字一起重新转换，
  后打的音节可以改变前面的选字。
- 中间敲的标点，以及切到英文后打的字母、数字和空格，都成为这句的一部分，
  前后的中文一起转换。
- 选定的字保持固定；粘贴的文字会把两边分成两段。
- 空格确认全部待上屏文字，再按一次空格才输入空格。
- =ESC= 暂存，回来后可以继续改；启用 Evil 时同时进入 normal 状态。

** 分段视图

=wime-candidate-style= 为 =spans= 时不显示双拼串，
模型拿不准的字加波浪线，替代写法竖排在下方，整段统一编号。
按数字固定那一段，其余部分重新解码。

* 神经解码

需要约 6 GB 显存的 GPU。CPU 太慢（一句要十几秒），不适用。
下表的文件放在 =wime-data-directory= 下，各选项默认就指向这些位置。

| 内容         | 位置                         | 来源                                 |
|--------------+------------------------------+--------------------------------------|
| Python 环境  | =python/=                    | =neural/pyproject.toml= 和 =uv.lock= |
| 音节模型     | =wime-syllable-40m/=         | HF =0WD0/wime-syllable-40m=          |
| 通用语言模型 | =rescorers/Qwen3.5-2B-Base/= | HF =Qwen/Qwen3.5-2B-Base=，固定版本  |

在 wime 目录执行：

#+begin_src sh
D="${XDG_DATA_HOME:-$HOME/.local/share}/wime"
UV_PROJECT_ENVIRONMENT="$D/python" uv sync --frozen --project neural --extra cuda
"$D/python/bin/hf" download 0WD0/wime-syllable-40m \
    --local-dir "$D/wime-syllable-40m"
"$D/python/bin/hf" download Qwen/Qwen3.5-2B-Base \
    --revision b1485b2fa6dfa1287294f269f5fb618e03d52d7c \
    --local-dir "$D/rescorers/Qwen3.5-2B-Base"
#+end_src

=--extra= 按显卡选择 PyTorch：

| 显卡                   | =--extra= |
|------------------------+-----------|
| NVIDIA（CUDA 13 驱动） | =cuda=    |
| AMD（ROCm 7.2）        | =rocm=    |
| Intel                  | =xpu=     |
| Apple 芯片             | =mps=     |

worker 自动使用找到的第一块 GPU。只在 NVIDIA 上测过。
=HF_ENDPOINT= 可指向 Hugging Face 镜像。然后启用：

#+begin_src emacs-lisp
(require 'wime-neural)
(wime-neural-mode 1)
#+end_src

worker 在后台常驻，首次启动要加载模型。
=wime-decoding= 选择中文的转换方式：

| 值               | 转换                                               |
|------------------+----------------------------------------------------|
| =hybrid=（默认） | 词格立即给出结果，停键后模型的整句结果排在前面     |
| =neural=         | 只用模型；回来前新音节显示按键，空格和数字等它回来 |
| =lattice=        | 只用词格                                           |

=neural= 打不出模型不认识的字。
worker 出错、超时或缺少文件时，三种方式都由词格转换。

* 工作方式

打字时，wime 在词库上做词格搜索：
按双拼码查词，按词频、每词罚项和可选的 octagram 搭配分打分，
辅助码和声调是硬约束。追加、退格时复用仍然有效的前缀。

停键 40 ms 后，输入发给本地的 GPU worker（=neural/gpu-worker.py=）。
它逐字做 beam 搜索：音节模型（=neural/transducer.py=）根据左文和
每个音节的声母、韵母、声调给出汉字概率，加权上 Qwen 的概率；
词库的读音、辅助码、声调和已选定的字是约束。
结果回来时输入没变，就排在词格候选前面。
词库里记录了各方案按键对应的声母和韵母，所以各方案共用同一个模型。

音节模型只认识约 12,400 个汉字。
词库里更生僻的字仍在词格候选中，用辅助码筛出来最快。

* 上屏记录与学习

两者都默认关闭。

#+begin_src emacs-lisp
(setq wime-user-database (expand-file-name "user.sqlite3" wime-data-directory))
#+end_src

设置后，每次上屏在本地记录按键、文字、wime 最初给的读音
和最多 64 字的光标前文，可用来检查输入法的实际表现。

再设 =(setq wime-learn t)=，与首选不同的上屏会被记成学到的读音：
不同的片段扩展到同键下最短的词典词（至少两字），
以后同样的按键优先给出它；同键上屏了别的读音就忘掉。
学到的读音在上下文需要别的词时也会胜出，所以默认不启用。

=M-x wime-history= 查看上屏记录，=M-x wime-memory= 管理学到的读音，
=M-x wime-memory-at-point= 查找光标处的学习词语；
在这两个 buffer 里按 =C-h m= 查看按键。
要全部清除，退出 Emacs 后删掉数据库文件。

* 词库与方案

=schemes/*.json= 定义每个方案的声母键、韵母键、零声母和整音节别名。
=gen/wime_gen.py= 只用 Python 标准库，从万象拼音的
[[https://github.com/amzxyz/rime-wanxiang/releases/tag/dict-nightly][=rime-wanxiang-moqi-fuzhu.zip=]]
生成按双拼码索引的 SQLite 词库，保留辅助码和声调：

#+begin_src sh
python3 gen/wime_gen.py --rime-data /path/to/unzipped \
    --scheme schemes/flypy.json --database wanxiang-flypy.db
#+end_src

=--rime-data= 是含 =wanxiang_pro.dict.yaml= 的目录。
自定义方案时复制一份 JSON 修改。词库记录每组键对应的声母和韵母，
神经解码据此读取新方案；两个音节共用一组键时，模型只看到其中一个。

* 开发

#+begin_src sh
make test-elisp
make test-python PYTHON=/path/to/python
#+end_src

ERT 测试使用临时的小词库，不读个人记录，不需要模型或网络；
=WIME_TEST_DATABASE=/path/to/wanxiang.db= 改用完整词库。
Python 测试只需 PyTorch 和 safetensors，在 CPU 上用小模型检查解码和 worker 协议。

=neural/= 和 =test/= 里的训练、语料和评测脚本是开发者的研究工具，
依赖作者 monorepo 中的其他部分和本地数据，不提供外部复现支持。
octagram 打分模块（=grammar.cc=）和 =BUILD.bazel= 等文件也只在 monorepo 中构建；
没有它时 wime 不使用 octagram。
